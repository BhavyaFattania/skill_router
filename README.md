# Skill Router

A production-quality TypeScript implementation of a recall-oriented skill router for AI agents. Given a user task and an installed skill catalog, the system retrieves likely skills via hybrid search, asks a fast LLM to make the final selection, applies confidence thresholding, and handles the "no match" case gracefully.

## Approach & Architecture

The router uses a **two-stage pipeline**:
1. **Hybrid Retrieval (Vector + Keyword):** It combines dense cosine similarity (using local LanceDB) and sparse keyword search (BM25). The scores are merged using Reciprocal Rank Fusion (RRF) to retrieve the Top K candidate skills.
2. **LLM Selection & Thresholding:** The Top K candidates are passed to an LLM (Qwen 3.5 Flash via OpenRouter). The LLM selects the exact required skills and returns a confidence score. If the score falls below a user-defined threshold, the router outputs nothing (handling the "no-skill" case).

### Assumptions & Tradeoffs
- **Context Stability vs. Latency:** By sending only the Top K candidates to the LLM (instead of the entire catalog), the context size remains fixed at ~1500 tokens regardless of how many skills are installed. The tradeoff is an additional network hop, bringing routing latency to ~5 seconds.
- **API vs. Local Models:** Due to TypeScript constraints and the slow speed of local CPU transformers, the embedding generation and LLM selection rely on external APIs (OpenAI and Qwen via OpenRouter). In a production environment, these would be swapped for local Python microservices running on CUDA to drastically reduce latency.

## Dataset Design

The evaluation dataset was intentionally designed to test hard cases and expose the router's blind spots.

### Composition
- **`skills.json` (~50 skills):** Rather than just a name and description, skills are enriched with `triggerConditions`, `examples`, `limitations`, `inputTypes`, `outputTypes`, and `intentPatterns`. This drastically increases the semantic "surface area" for the vector search to latch onto.
- **`tasks.json` (150 tasks):** Standard user queries across different domains, ranging from simple direct requests to complex multi-skill workflows. 
- **`special_tasks.json` (30 tasks):** Highly difficult edge-case queries generated by prompting a "thinking model" about how human prompts might fail. These include tasks with out-of-vocabulary terms, superficial similarity to multiple skills, and explicit "no-skill" traps.

### Relevance Labels & Ambiguous Judgment Calls
Relevance labels were assigned manually. The guiding principle was strict necessity: a skill was only labeled as "expected" if the task absolutely required it to succeed.

**Ambiguous Cases:**
Many judgment calls were genuinely ambiguous. For example, a task like "Analyze this repo and tell me what's wrong" could theoretically trigger a `GitHubRepoAnalyzer` and a `Linter`. However, if the intent was just a high-level summary, the linter isn't strictly necessary. In these ambiguous cases, I kept the ground truth labels tight and minimal. As a result, the router sometimes suffers "false positives" because the LLM tries to be overly helpful and selects auxiliary skills. I kept these hard cases in the dataset because an easy dataset that hides weaknesses is useless; the failure analysis documents exactly why these happen.

## Installation & Running

### Prerequisites
- Node.js (v18+)
- An OpenRouter API Key (for embeddings and LLM selection)

### 1. Install & Configure
Clone the repository and install dependencies:
```bash
npm install
cp .env.example .env
```
Open `.env` and add your `OPENROUTER_API_KEY`.

### 2. Build the Vector Index
Run the indexing script to embed the `skills.json` catalog and store it in LanceDB:
```bash
npm run index
```

### 3. Run the Dashboard & API
Start the backend Express server and the frontend Vite React app concurrently:
```bash
npm run dev:backend
npm run dev:frontend
```
- **Frontend Dashboard:** `http://localhost:5173`
- **Backend API:** `http://localhost:3001`

Use the dashboard to send prompts, toggle installed skills, and tweak the Top K / Threshold sliders in real-time to see how the router behaves (especially the "nothing fits" fallback).

## Evaluation & Commands

To run the automated evaluation suite against the dataset and generate the `evaluation-report.json`:
```bash
npm run evaluate
```

To run the evaluation specifically against the edge-case special tasks (generates `special-evaluation-report.json`):
```bash
npm run evaluate:special
```

**Other Commands:**
- `npm test`: Run Vitest tests
- `npm run typecheck`: Run strict TypeScript checks
